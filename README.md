# Лабораторная работа по проектированию баз данных

Выполнила: Глебова Надежда M3203

## Предметная область

Учет данных для автоматизации деятельности приюта для домашних животных. В системе сохраняются сведения о животных, содержащихся в приюте, их здоровье, лицах, сотрудничающих с приютом, финансовом обороте, помещениях и работниках приюта.

## Функциональные требования

### Поступление животного в приют

- При поступлении животного в приют в систему сохраняются основные данные (кличка, вид и порода (выбираются из соответствующих списков), пол, примерная дата рождения), а также дата поступления животного; отмечается сотрудник, который регистрировал животное.
- В системе есть возможность оставить комментарий к поступлению в свободной форме (например, об общем состоянии животного и обстоятельствах его поступления в приют).

### Пребывание животного в приюте

- Система позволяет отмечать и отслеживать состояние животного: состоит на лечении; временно на передержке; нашло постоянного хозяина; и т.д. (состояния описаны в соответствующем списке).
- В системе фиксируется помещение, в котором в данный момент размещено животное, дата начала и окончания размещения (вторая заполняется со временем).

### Передача животного новым хозяевам

- Для того, чтобы забрать животное (на постоянной основе или на передержку), необходимо заполнить заявку, о которой в системе сохраняется следующая информация: дата заявки, сведения о заполнявшем ее человеке, какое животное он хочет забрать, статус рассмотрения заявки (выбирается из соответствующего списка).
- О возможных хозяевах при подаче заявки (если они еще не сохранены в системе) сохраняются контакты, опционально - адрес, а также основные сведения: пол, дата рождения, семейное положение (выбирается из соответствующего списка) - чтобы иметь возможность принимать решение по целесообразности передачи животного.
- В системе фиксируются сведения о конкретных случаях передачи животного новым хозяевам: дата передачи животного, информация о хозяевах, сотрудник, который регистрировал передачу животного.

### Здоровье животных

- Возникшие/обнаруженные у животного проблемы со здоровьем фиксируются в системе: отмечается диагноз (выбирается из соответствующего списка), ветеринарная клиника, в которой животное проходит лечение, даты начала и окончания лечения (вторая заполняется со временем).
- Для каждого конкретного случая заболевания сохраняются подробности лечения: какое лечение (лекарство/процедура) было назначено (выбирается из соответствующего списка), комментарий в произвольной форме, даты начала и окончания применения лечения (вторая заполняется со временем).

### Поставки товаров и услуг для приюта

- В системе хранится информация о поставщиках (товаров и услуг, в том числе медицинских): контакты, адрес, даты начала и окончания сотрудничества (вторая заполняется со временем).
- В систему заносится информация о поставках: дата поставки, что поставляется (выбирается из соответствующего списка), в каком количестве, цена за единицу (в одной поставке может быть несколько разных товаров).

### Денежные пожертвования

- Пожертвования заносятся в систему: дата, сумма пожертвования, сведения о благотворителе, способ перевода денег (выбирается из соответствующего списка), в свободной форме назначение пожертвования (на что должны пойти деньги).
- При первом пожертвовании благотворитель заносится в систему (сохраняются данные о контактах, адресе (опционально), типе благотворителя (физическое или юридическое лицо)).

### Лица

- В системе хранятся данные о сотрудниках, благотворителях, поставщиках и потенциальных/реальных хозяевах (тех, кто забирал когда-либо животных из приюта на передержку или на постоянной основе).
- Одно и то же лицо может совмещать в себе несколько функций (например, быть одновременно благотворителем и хозяином животного).

### Сотрудники

- При приеме на работу в системе фиксируются следующие данные о сотруднике: контакты, адрес (опционально), пол, дата рождения, должность (выбирается из соответствующего списка) и дата начала работы, дата окончания работы (остается незаполненной, пока сотрудник состоит на должности).
- Один сотрудник может состоять на разных должностях в разные (или накладывающиеся друг на друга) промежутки времени.

### Помещения приюта

- Информацию о всех помещениях приюта заносится в систему (тип помещения (выбирается из соответствующего списка) и в свободной форме его расположение на территории приюта).

### Списки

- Для всех упомянутых списков поддерживается добавление, удаление, редактирование записей.

## Схема БД

Схема нормализована до 3НФ:

- не содержит транзитивных зависимостей;
- неключевые атрибуты полно зависят от первичных ключей;
- атрибуты не содержат многозначных значений.

## Бизнес-аналитика (BI-метрики)

### Выбор таблицы для аналитики

Для аналитики была выбрана таблица `donations`:

- довольно быстро растет (история пожертвований приюту), подвержена постоянным изменениям (`INSERT` при новых платежах, `UPDATE` при изменении сумм, `DELETE` при отмене операций), основная операция - `INSERT` (поступление новых пожертвований);
- есть поля, которые отражают время, категории, числовые показатели;
- метрики пожертвований критически важны для аналитики приюта для животных, так как от пожертвований в первую очередь зависит функционирование приюта.

### Поля, использованные в метриках

| Поле | Тип | Описание | Роль в аналитике |
|:--:|:--:|:-------:|:----------:|
| `amount` | DECIMAL(10,2) | Сумма пожертвования | Используется для вычисления общей суммы пожертвований, для построения графика распределения пожертвований по дням, для вычисления процента пожертвований относительно типа платежа |
| `payment_type_id` | INTEGER (FOREIGN KEY) | Идентификатор типа платежа | Используется для вычисления процента пожертвований относительно типа платежа |
| `date` | TIMESTAMP | Дата пожертвования | Используется для построения графика распределения пожертвований по дням |
